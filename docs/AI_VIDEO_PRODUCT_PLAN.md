# PromptFilm AI 视频产品方案

## 0. 设计稿全局规则

以下规则固定展示在 `.pen` 设计稿最上方，并适用于阶段一至阶段四的新增、改版与验收：

- Android 所有一级、二级、三级及异常分支页面统一展示四个底部 Tab，显示文案和顺序固定为 `VIDEO → AI CREATE → STORIES → STUDIO`；页面只切换当前选中态，不改变导航结构、图标、颜色或间距。
- 页面按“入口 Tab”继承归属：从 `VIDEO` 进入的模板详情、素材、生成、支付和结果页继续保持 `VIDEO` 选中；从 `AI CREATE`、`STORIES`、`STUDIO` 进入的后续页面同理。二级及更深页面同时保留返回按钮。
- 页面基础命名统一为 `NN CUR-页面名`：`NN` 是两位展示顺序，`CUR` 是全稿唯一的两位字母/数字页面码。真正创建新路由的二级、三级和分支页使用 `NN PRE-CUR页面名`，`PRE` 必须是主路径中可直接进入当前页的上一页面码，例如 `02 AB-模板首页`、`03 AB-AC模板详情与上传 · 单人`。同一路由的展开、滚动、支付恢复等状态稿使用 `NN CUR-页面名 · 状态`，不写 `PRE`，也不显示标准返回键，但必须提供收起、关闭或自动恢复动作。多入口页面只在名称中记录主入口，其余入口写入页面交互说明；入口变化时同步更新画板名、画板上方标题和交付清单。
- 每个阶段的 Android 画布按激活 Tab 分组。同一 Tab 的主流程、二级页、三级页和分支页从左到右按业务顺序连续排列，页面间距不得小于 24 px；切换到另一个 Tab 时另起一行，并增加明显的纵向组间距。一个 Tab 页面超过单行容量时，可在同一分组内续排下一行，但不得与其它 Tab 混排。设计系统和阶段一至阶段四的顶层区域按约 200 px 的纵向安全间距排列；新增页面或组件后必须重新执行重叠检查。
- 新增页面在设计前必须先检索对应端的标准 UI 组件库。已有组件必须使用组件实例和状态覆盖；图标开关、选中/默认/禁用/完成状态及宽高规格均作为同一组件族的变体管理，不复制成彼此无关的组件。
- 新组件只有在现有组件族确实无法表达新的业务语义或结构时才可建立；建立后必须同步补入 Android 或管理后台组件库，并复用既有主题变量、颜色池、字体、圆角、描边、阴影和状态语义。
- Android 每页保留系统状态栏安全区，正文、底部 CTA 和四 Tab 导航不得相互遮挡；二、三级页面使用标准返回组件。视频 Banner 和场景预览使用真实场景图，不以纯色块代替媒体封面。
- 管理后台继续使用独立的左侧全局导航；一级业务页和二级详情/编辑页均保留侧栏，二级页面显示返回键。标题路径允许追加当前 Tab 作为第三段，但不形成第三级路由。运营可见的字段、状态、说明和操作提示尽可能使用中文。
- 交付前统一检查：页面编号与路径顺序、入口 Tab 和选中态、返回按钮、标准组件实例、状态栏、真实封面、组间距、异常分支及交互闭环。

## 1. 产品定位与首版目标

- 核心定位：保留通用 AI 视频生成能力，新增面向饭圈用户的“我＋TA”连续恋爱短片体验，让用户从单次生成进入可持续消费的章节故事。
- 核心承诺：用户创建一个长期关系档案，逐章生成与 TA 的互动片段，完成六章后合成一部 60–90 秒竖屏终章电影。
- 核心路径：`发现模板或继续故事 → 进入关系档案 → 选择本章场景 → 生成并选定正片 → 解锁下一章 → 合成终章 → 下载或分享`。
- 原有能力继续保留：模板视频、自由提示词、文生视频、图生视频、参考生视频、作品管理、积分和 VIP 均不被 Stories 替换。
- 首发范围：海外英文商店、18 岁以上用户、应用内无公开作品流；运行时默认及兜底消息使用英文，项目说明、代码注释和公开接口字段说明使用中文。
- 首版亲密内容覆盖暧昧、牵手、拥抱、约会、告白和亲吻；裸露与明确性行为不进入当前商店版本，未来如需提供，作为独立发行、支付和合规项目重新立项。

## 2. 信息架构与导航

底部导航由现有结构扩展为四个入口：

- `VIDEO`：模板发现与单次视频生成首页，保留 Banner、快捷入口、Hot、Romance、Birthday、Fantasy、Idol 等内容。
- `AI CREATE`：保留自由提示词、文生视频、图生视频、参考生视频、模型和生成参数设置。
- `STORIES`：新增关系档案、章节进度、生成版本、正片选择和终章电影管理。
- `STUDIO`：保留个人作品、下载记录、积分、VIP、订单、订阅和账号设置。

客户端从左到右固定为 `VIDEO → AI CREATE → STORIES → STUDIO`，`STUDIO` 始终位于 `STORIES` 右侧；所有 Android 页面都展示同一个四 Tab 底部导航组件，并按入口来源切换选中态。

页面层级与返回规则固定如下：

- 阶段四一级页面：`01 D0-Video 首页 · Your Stories 增量`、`02 D1-Stories 首页 · 空状态`、`03 D2-Stories 首页 · 进行中`、`16 DF-Stories 已完结状态`。一级页面不显示返回按钮。
- 阶段四二级页面：`04 D1-D3创建关系 · 第一步`、`05 D3-D4创建关系 · 第二步`、`06 D2-D5关系详情 · 六章地图`、`12 D5-DB终章解锁`。二级页面左上角必须显示返回箭头，返回进入该页面的一级来源；创建流程第二步返回第一步。
- 阶段四三级页面：`07 D5-D6章节场景模板选择`、`08 D6-D7章节生成中与任务恢复`、`09 D7-D8章节多版本选片`、`10 D6-D9余额不足`、`11 D7-DA生成失败与退款`、`13 DB-DC终章电影合成中`、`14 DC-DD终章电影播放与交付`、`15 DD-DE更换正片`。三级页面左上角统一显示返回箭头，不使用关闭 `×` 代替返回。
- 阶段三 Android 只保留有现有入口支撑的六个页面：`01 A9-C0分享与举报`、`02 AE-C1历史与过期状态`、`03 AE-C2设置与隐私`、`04 C2-C3数据导出完成`、`05 C2-C4隐私政策与条款`、`06 C2-C5设置选项编辑`。当前阶段移除删除账户入口、确认页和结果页；隐私与合规入口由 `Privacy Policy · Terms of Use` 承接。
- `08 A7-自由创作 · 设置展开状态`、`12 AB-支付成功续接 · 恢复创作状态`、`03 B2-视频模板流 · 上滑分类吸顶状态` 都是同路由状态稿，不是二级页面；分别通过收起面板、自动恢复或滚动返回原状态。`04 B3-我的与钱包` 是由底部 `STUDIO` 直接进入的阶段二根页增强版本，也不是从 `15 AE` 下钻的二级页面。上述四页不显示标准返回键。
- 返回时保留关系、章节、具体场景模板、素材、报价和活动任务 ID；生成中或合成中返回只离开当前页面，不取消任务、不重复扣费。
- Android 所有页面顶部先保留统一的 54 px 系统状态栏安全区，再排列页面返回、标题和更多操作；页面导航不得占用或覆盖系统时间、网络和电量区域。`08 D6-D7`、`09 D7-D8`、`11 D7-DA`、`13 DB-DC`、`14 DC-DD`、`15 DD-DE` 与其它二、三级页面执行同一规则，弹窗遮罩可以覆盖状态栏，但底层导航仍须按安全区排版。

Stories 新页面必须复用现有 `PromptFilm Design System` 的主题变量、暗色背景、粉紫高亮、颜色池、圆角、描边、字体、按钮、顶部导航和底部导航组件，不建立平行主题或另一套 UI 组件。章节与场景模板的媒体占位统一使用对应剧情的场景图并叠加现有暗色蒙层；不以纯色背景色块冒充封面或视频预览。

设计系统画布按使用端拆为两区：`PromptFilm Android Design System` 放在“阶段一 · MVP - Android”上方，收纳移动端基础控件、视频业务组件和 Stories 客户端组件；`PromptFilm Admin Design System` 放在“阶段一 · MVP - 后台”上方，收纳后台导航、指标、表格、返回、状态和 Stories 运营组件。两区继续绑定同一组 `pf-*` 颜色与字体变量，拆分仅用于组件归属和画布导航，不复制主题或建立第二套颜色池。

Stories 组件复用和新增组件规范：

- 所有主操作统一使用同一个 `Primary Action / Gradient` 组件族，通过 `Icon Off / Icon On` 变体控制左侧图标，并由实例覆盖图标和文案；Stories 不再维护独立主按钮组件。按钮宽高变化时圆角始终等于实例高度的 50%，例如 `44/22、50/25、54/27、62/31`，确保所有页面保持同一胶囊曲率。付费生成继续组合现有 `Credit Cost Badge / Default`；积分角标置于按钮右上角前景层，完整覆盖在按钮之上。
- 普通次级操作复用 `Button / Secondary`，危险操作复用 `Button / Danger`，禁用状态沿用现有灰色体系；白底按钮不再作为 Stories 主操作样式。
- Android 底部半屏弹窗统一采用 `Base → Subclass → Page Instance` 三层组件结构。`Android Bottom Sheet / Base` 只封装浮层外壳、圆角、描边、阴影、手势条、完整内容宿主和底部安全区；所有新增底部弹窗都必须继承该 Base。`Balance / Failure / Update Final / Settings / Final Delivery` 子类替换整个内容宿主，在子类内部实现图标、标题、说明、业务 UI、主次操作、状态和交互；页面只实例化对应子类，不直接重画弹窗。设计系统中的内容宿主仅用于表达组件契约，运行页面不得显示任何 `Content Slot` 占位文案。标准宽度为 336 px、左右安全间距为 12 px、底部预留 86 px 以避开 72 px 四 Tab 导航；弹窗高度由子类内容自动撑开，不锁定统一高度。余额不足、失败退款、更换正片、创作设置和 `14 DC-DD终章电影播放与交付` 均接入该组件族，主按钮继续复用 `Primary Action / Gradient`。
- 双人素材选择直接复用 `Segmented Control / Upload Mode / Compact`；Android 默认规格为 `184 × 30`，放在身份面板标题区右侧，不使用 `fill_container` 拉满面板。页面不改变选中胶囊、内边距、圆角、两段比例和字体。上传区域统一使用同一个可伸缩的 `Upload Slot / Dashed` 组件族，通过 `Size = Wide / Portrait` 表示 `250 × 166` 与 `144 × 142`，并由实例覆盖 `Upload photo / Person 1 / Person 2` 文案和强调色，不再维护 Stories 专属上传槽。
- 首页关系视频统一使用 `Story Progress Banner` 组件族，通过 `Default / Playing / Completed` 状态覆盖未开始、自动连播中和已完结关系；实例只覆盖真实场景封面、关系名称、当前章节、播放文案与六章进度，不单独复制卡片结构。Banner 和场景预览卡进入可视区域后静音自动播放 2–3 秒，不显示播放按钮；卡片内部不响应左右滑动，进度条不可点击或拖动。自动切章属于播放器行为，Banner 下方不再显示独立的 `Auto-next`、`Ready` 或 `Completed` 状态条。
- 场景预览统一使用 `Stories Scene Preview Card / Default|Selected`；章节列表统一使用 `Stories Chapter Media Row / Generated|Available|Locked`；生成版本统一使用 `Stories Take Card / Default|Selected`。
- 组件库按“组件族 + 状态/尺寸变体矩阵”展示。一个组件的不同状态必须位于同一组件族标题下并明确标识变体名，不得把 `Default / Selected / Locked / Generated` 或不同宽高样例排成彼此无关的多个组件；管理后台状态标签、章节行和场景卡片执行相同规则。
- 二、三级页面的返回入口统一使用 `Stories Back Button / Glass`。上述 Stories 组件全部放入现有设计系统的 `05 · STORIES COMPONENTS` 区域，不另建颜色变量或平行组件库。
- `05 D3-D4` 六章模板、`06 D2-D5` 章节列表、`09 D7-D8` / `15 DD-DE` Take 选片和 `12 D5-DB` 终章六章墙必须展示真实场景封面，并在图片上叠加现有暗色可读性蒙层；生成中、禁用和锁定状态通过透明度与既有状态色表达。
- 管理后台复用 `Admin Global Sidebar / PromptFilm`、`Admin Back Button / Default`、`Admin Metric Card / Default` 和原有后台卡片、表格、状态色；Stories 后台新增状态标签、章节行和场景卡片组件，统一收纳在现有设计系统的 `06 · STORIES ADMIN COMPONENTS`，不新增主题和颜色池。
- 管理后台的保存、刷新、新建、编辑、发布、重试、返还积分和回传统一复用 `Admin Action Button / Default` 组件族；通过 Primary、Secondary、Danger、Disabled 状态覆盖根节点颜色、描边、图标和文案，不为每个页面重画按钮。

连续章节能力作为新增业务线接入现有生成、素材、钱包和作品体系，不删除、改名或静默改变原有能力。

## 3. Video 首页设计

### 3.1 现有内容

- 保留全屏运营 Banner、播放预览、积分/VIP 入口和活动入口。
- 保留 AI Editor、Romance、Birthday 等快捷入口。
- 保留 Hot、Romance 及其它模板横向列表和模板详情页。
- First Kiss、Sunset Date、Movie Scene 等模板继续支持单次生成；适合连续剧情的模板可额外提供 `Start a Story` 入口。

### 3.2 Your Stories 模块

在保留原首页 Banner、快捷入口、Hot、Romance 等既有内容的基础上，以可运营排序的增量模块新增 `Your Stories`，负责故事发现和快速续接；当前设计稿默认放在既有模板发现内容之后：

- 没有关系档案：展示 `Create Your Story` 引导卡，说明“创建我与 TA 的六章电影”。
- 有进行中故事：以视频 Banner 展示关系名称、`Chapter N of 6`、当前章节、播放状态和六章进度。
- Banner 自动播放当前章 2–3 秒预览；单章播放结束后由播放器在同一 Banner 内自动切换下一章，完成第六章后回到第一章循环。用户不能通过横滑、点击进度条或拖动进度条手动切换卡片内部的章节/场景。
- 自动切换只由 Banner 内的章节标签、关系名、当前章节文案和六段进度表达；卡片下方不额外占用空间展示 `Auto-next` 提示行。
- 用户点击 Banner 进入该关系的章节二级页；二级页展示完整六章状态，并允许逐章播放 2–3 秒预览。
- 有多个关系：在同一个横向列表容器内实例化多个 `Story Progress Banner`，首屏完整显示当前关系并露出下一张卡片；用户横向浏览时只切换不同关系档案，不切换任一卡片内部的章节/场景。关系按最近互动时间排序，不把每个关系画成独立组件。
- 有生成中任务：展示当前章节与任务进度，点击后恢复原任务，不重复创建。
- 已完成故事：展示终章封面、`Watch Final Movie` 和继续创建新一季的入口。
- 首页只返回故事摘要；创建、编辑、版本管理和完整章节地图统一进入 Stories。

## 4. Stories 产品体验

### 4.1 创建关系档案

- 用户可以创建多个相互隔离的“我＋TA”关系档案。
- 创建时录入用户昵称、TA 昵称、用户参考照片和 TA 参考照片，并完成 18+、真人素材使用权及虚构用途确认。
- POV 模板只要求 TA 素材；双人模板要求用户与 TA 两个素材位。
- 首版不提供未经授权的明星官方目录，不使用“官方”“本人参与”等可能造成关联误解的表述；TA 名称和素材均由用户私密创建。
- 更换任一核心人物时创建新关系档案，不直接替换已有关系的身份素材，避免破坏历史章节的人物一致性。
- 关系状态固定为 `ACTIVE`、`COMPLETED`、`ARCHIVED`；归档只隐藏首页入口，不删除历史作品。

### 4.2 六章关系线

Stories 采用“故事模板包 + 章节场景模板”的双层机制。每个故事模板包固定六章及每章的剧情目标；同一章节下允许运营配置多个可选场景模板，每个场景模板的地点、剧情节拍、镜头、人物动作、互动方式、时长区间和生成参数均预先固定。用户选择故事模板包并提供“我＋TA”身份素材，进入章节后再从运营提供的场景模板中选一个，不自由修改剧情、镜头或动作。

运营可以持续配置多个模板包，例如：

- 青春校园：初见 → 靠近 → 误会/吵架 → 和好 → 热恋 → Kiss。
- 酒吧偶遇：对视 → 搭讪 → 共饮 → 暧昧靠近 → 牵手 → Kiss。
- 办公室暗恋、久别重逢、偶像后台、雨夜电影感等其它题材，也使用各自固定的六章剧情弧。

每个章节场景模板都提供独立的 2–3 秒免费预览。预览卡进入可视区域后自动静音播放，不显示播放按钮，不支持通过横滑切换场景；点击卡片只改变场景选中状态。预览使用运营上传并审核通过的固定成片，不触发人物替换、生成任务或积分扣除；正式生成使用用户最终选中的场景模板，并仅将模板演员替换为用户与 TA。

例如“青春校园 / 第三章：吵架”可以同时提供“回家路上”“校园操场”“网吧门口”等场景模板。用户逐个试看后明确选中一个版本再进入报价和生成；运营可以持续扩充同一章节的场景库存，并通过曝光、试看、选中、付费和生成完成率判断高转化场景。

每章统一流程为：

`选择固定故事模板 → 预览六章 → 进入可生成章节 → 浏览该章场景模板 → 免费预览 2–3 秒 → 选中具体场景 → 显示积分价格 → 创建人物替换任务 → 查看结果 → 选为正片 → 解锁下一章`

- 单章目标时长为 8–12 秒，默认比例为 9:16。
- 用户可以在章节未解锁时观看该章各场景模板的 2–3 秒预览，但只能按顺序创建正式生成任务。
- 场景模板选中状态在报价前保存；余额不足、购买返回或应用重启后恢复到原章节和原场景，不要求用户重复选择。
- 固定模板版本写入所有章节任务、字幕和终章标题，不在首版引入单章自由改写或实时陪伴聊天。
- 每次成功生成形成一个独立版本；重新生成不会覆盖旧版本。
- 用户明确选定“正片版本”后，本章状态才变为 `SELECTED` 并解锁下一章。
- 已完成章节可以重新生成或更换正片版本，不回退已解锁的后续章节。
- 章节状态固定为 `LOCKED`、`AVAILABLE`、`GENERATING`、`READY`、`SELECTED`。

### 4.3 终章电影

- 六章均选定正片版本后解锁终章合成。
- 服务端按章节顺序拼接六段视频，统一画幅、帧率和音量，并加入片头、章节过渡、已授权背景音乐和结尾卡。
- 目标输出为 60–90 秒、9:16 的 MP4 视频。
- 首次合成以及用户更换正片版本后的重新合成都不扣生成积分。
- 合成请求必须保持幂等，只接受同一关系下六个状态为成功的正片版本。
- 终章同时出现在 Stories 和 Studio，可下载或调用系统分享。
- 导出作品不强制叠加可见的 `AI-generated` 文案；应用内结果页持续明确内容由 AI 生成，并在格式支持时写入内容来源元数据。

## 5. 模板、自由创作与结果交付

- 单次模板继续支持“模板内置目标人物”和“用户替换目标人物”，模板明确声明需要一张或两张照片。
- 自由创作继续提供模型、提示词、可选参考图、比例、时长、清晰度、智能改写、水印和预计积分。
- 自由创作配置接口一次返回当前已启用模型、输入要求、比例、时长、分辨率、音频开关和完整的有效积分组合。用户点击 `720p / 1080p` 或切换其它参数时，客户端只在本地匹配组合并即时更新预计积分，不为每次点击单独请求接口；真正提交前必须重新向服务端获取短时有效报价，最终扣费以报价快照为准。
- 自由创作的常用参数在 `07 A6-自由创作` 与同路由状态稿 `08 A7-自由创作 · 设置展开状态` 内完成，不新增没有入口的独立“高级创作参数”页面。
- 模板和 Stories 共用素材上传、报价、生成任务、进度、结果播放、下载、系统分享、重做和举报能力。
- Stories 模板额外声明故事模板包、模板版本、固定六章顺序、章节剧情目标、章节场景模板列表、视角类型、人物槽位、固定剧情与镜头参数、每个场景的 2–3 秒预览资产和终章适配信息。
- 余额不足时保存关系、章节、素材选择和生成参数；购买成功后恢复原章节流程。

## 6. 商业化设计

- 六个章节从第一章开始全部按单次生成扣积分，不设置免费首章，也不保证新用户赠送足以完成首章的积分。
- 用户对结果不满意时可以重新生成；每次重新生成作为新任务再次扣除积分，已有结果继续保留。
- VIP 是周期积分订阅：按周期发放积分，并提供积分折扣、优先队列、1080p 和其它动态权益；VIP 用户生成章节时仍按次扣除积分。
- 技术失败、供应商失败或结果被平台自动拦截且未向用户交付时解冻或退回积分；成功交付后正常结算。
- 章节页持续展示 `Complete all 6 chapters to unlock your final movie`、当前进度和预计剩余积分，引导用户完成整季。
- 月订阅、年订阅、积分包、章节价格、VIP 折扣和运营赠送均由后端动态配置，不在客户端硬编码生产值。
- 埋点覆盖故事模块曝光、关系创建、章节曝光、场景模板曝光、场景预览、场景选中、报价、生成、重生成、正片选择、章节完成、终章合成、分享、付费墙和购买。

核心业务指标包括：

- 关系档案创建率、首次付费生成率和首章完成率。
- 各章完成率、章节间流失率、平均重生成次数和六章完结率。
- 终章合成率、终章分享率、单关系平均积分消耗和生成毛利。
- 自动拦截率、失败退款率、任务恢复率和举报率。

## 8. 后端、数据与任务状态

### 8.1 领域划分

- 后端按 `auth`、`catalog`、`media`、`generation`、`story`、`wallet`、`billing`、`compliance` 领域组织。
- 新增关系档案、季度、章节、剧情选择、生成版本、正片选择和终章合成数据模型。
- 原有视频任务接口继续保留，新 Stories 接口以增量方式新增，不删除、重命名或静默重定向旧路由。

### 8.2 生成与合成状态

单段生成任务继续使用：

`RESERVED → QUEUED → SUBMITTED → RUNNING → SUCCEEDED / FAILED / CANCELLED / EXPIRED`

终章合成任务使用：

`QUEUED → DOWNLOADING → COMPOSING → UPLOADING → SUCCEEDED / FAILED / EXPIRED`

- 创建生成任务时使用报价 ID 和幂等键原子冻结积分；成功后结算，明确失败或供应商接单前取消时解冻。
- 章节生成版本关联关系、章节、供应商任务和当次剧情选择；任务重试不得复用已消费的幂等键。
- 正片选择更新时使旧终章标记为过期，但不删除旧终章；用户可发起新的免费合成。
- 终章合成校验六个正片版本均成功、属于同一关系且按章节顺序完整。
- 阿里模型继续通过 `VideoModelPort` 隔离；终章合成通过独立 `VideoComposerPort` 隔离具体转码实现。

### 8.3 素材保留

- 普通单次创作源图保留 24 小时，普通生成结果保留 7 天。
- Stories 身份参考图在用户明确同意后随关系档案保留，直到用户删除该关系。
- Stories 的章节版本和终章随关系档案保留；用户删除关系时进入异步删除流程并停止后续生成。
- 后台只保存 OSS 资产标识和受控预览地址，不展示模型密钥、永久签名地址或用户原始凭据。

## 9. 客户端接口规划

本节描述供 Android 与 iOS 接入的目标合同，路由前缀统一为 `/api/v1`。当前仓库已验证实现的业务接口只有 `GET /health`，以下接口均属于后续开发规划，不代表现有服务已经注册；正式开发时需同步 OpenAPI、接口测试和客户端模型，已经发布的接口只允许兼容性增量扩展。

### 9.1 通用合同

- 响应沿用 `ApiEnvelope<T>`：`code` 为稳定机器码，成功时为 `OK`；`message` 为可直接展示的英文兜底文案；`data` 为具体业务数据，是否允许为空由单个接口合同声明。请求追踪 ID 通过响应头 `X-Trace-Id` 返回。
- 客户端请求至少携带 `Authorization`、`X-App-Id`、`X-Platform`、`X-Client-Version`、`Accept-Language` 和 `X-Request-Id`；无需登录的目录接口可省略 `Authorization`。创建任务、购买校验、资产变更和终章合成额外携带 `Idempotency-Key`。
- 时间统一使用 UTC 的 ISO 8601 字符串，例如 `2026-08-22T08:30:00Z`；积分为整数，禁止浮点；金额返回最小货币单位、币种和商店展示文案，客户端不自行换算生产价格。
- 列表默认使用 `items / nextCursor / hasMore` 游标分页；后台管理表格可单独使用 `page / pageSize / total`。媒体接口只返回资产 ID 和短时 URL，客户端不得保存永久签名地址。
- 可缓存的目录或配置响应返回 `configVersion` 或 `publishedVersion`，并支持 `ETag / If-None-Match`。报价、钱包、订单和任务状态始终以实时响应为准。
- 客户端只按 `code`、HTTP 状态或明确枚举进行程序分支。建议首批稳定错误码包括 `AUTH_REQUIRED`、`CONFIG_VERSION_STALE`、`QUOTE_EXPIRED`、`COMBINATION_DISABLED`、`INSUFFICIENT_CREDITS`、`IDEMPOTENCY_CONFLICT`、`TASK_NOT_FOUND`、`TASK_NOT_RETRYABLE` 和 `CONTENT_BLOCKED`。

### 9.3 自由创作配置、组合积分与报价

`GET /api/v1/ai-create/config` 至少返回以下业务结构：

- `configVersion`、`generatedAt` 和可选 `expiresAt`，用于判断本地缓存是否仍可使用。
- `models[]`：包含 `modelId`、展示名称、说明、图标资产、VIP 限制、输入图片数量、支持能力、默认参数和启用状态；不返回供应商密钥、内部成本或原始参数映射。
- `options`：统一声明 `ratios`、`durationsSeconds`、`resolutions`、`audioModes`、图片限制、提示词长度和默认值。某个模型不支持的选项通过模型能力范围排除。
- `pricingCombinations[]`：每项包含稳定 `combinationId`、`modelId`、比例、时长秒数、分辨率、音频开关、所需积分和启用状态；组合必须完整匹配后才能展示可提交价格。

用户点击 `720p / 1080p`、切换比例、时长或音频时，客户端只根据当前 `modelId + ratio + durationSeconds + resolution + audioEnabled` 本地查找组合，不逐次访问网络。没有匹配项时禁用提交并提示该组合暂不可用。用户点击生成后调用报价接口，报价响应覆盖页面上的预计积分；若服务端返回 `CONFIG_VERSION_STALE` 或 `COMBINATION_DISABLED`，客户端刷新配置、保留仍兼容的选择并要求用户重新确认，不静默按旧价格提交。

报价返回 `quoteId`、`businessType`、`combinationId`、`baseCredits`、`discountCredits`、`finalCredits`、`currency=credits`、`expiresAt` 和不可变 `parameterSnapshot`。创建任务只接受未过期且属于当前用户、App 和参数组合的报价；服务端在同一事务中校验报价、冻结积分并创建任务。

### 9.4 模板生成与自由创作任务合同

- 模板生成请求使用 `businessType=TEMPLATE`，携带 `templateId`、`publishedVersion`、按槽位排序的 `personAssets[]` 和报价 ID。服务端从已发布模板快照读取生产源视频、人物映射、提示词、模型和工作流，不信任客户端回传这些内部字段。
- 自由创作请求使用 `businessType=AI_CREATE`，携带 `modelId`、提示词、可选参考资产、比例、时长、分辨率、音频开关、组合 ID 和报价 ID。服务端再次校验所有参数属于同一启用组合。
- 任务响应至少包含 `taskId`、`businessType`、`status`、`progressPercent`、`currentStep`、`attemptCount`、`creditStatus`、`frozenCredits`、`createdAt`、`updatedAt`、可选 `result` 和可选 `failure`。`failure` 只暴露稳定错误码、英文文案和是否允许运营补偿，不透传供应商异常原文。
- 成功结果返回 `assetId`、短时播放地址、封面地址、比例、时长、分辨率和是否含音频；短时地址到期后通过任务详情或媒体下载接口刷新。

| 创建关系 | `POST /api/v1/stories` | 携带故事模板、人物昵称、身份资产和确认记录；使用幂等键 |
| 关系详情 | `GET /api/v1/stories/{storyId}` | 返回关系快照、六章状态、选定正片和终章摘要 |
| 归档或删除 | `PATCH /api/v1/stories/{storyId}`、`DELETE /api/v1/stories/{storyId}` | 归档只隐藏入口；删除进入异步清理并返回删除任务状态 |
| 章节场景 | `GET /api/v1/stories/{storyId}/chapters/{chapterId}/scenes` | 返回已发布场景模板、2–3 秒预览和当前选择 |
| 章节报价 | `POST /api/v1/stories/{storyId}/chapters/{chapterId}/quotes` | 返回章节价格、VIP 折扣、场景和人物快照 |
| 创建章节任务 | `POST /api/v1/stories/{storyId}/chapters/{chapterId}/tasks` | 校验顺序解锁、场景、报价和幂等键，返回活动任务 |
| 查询 Takes | `GET /api/v1/stories/{storyId}/chapters/{chapterId}/takes` | 返回全部成功版本和当前正片，不覆盖旧 Take |
| 选择正片 | `PUT /api/v1/stories/{storyId}/chapters/{chapterId}/selected-take` | 只接受同关系、同章节且成功的 Take，重复选择保持幂等 |
| 终章合成 | `POST /api/v1/stories/{storyId}/final-movies` | 校验六章正片，免费创建或重建终章合成任务 |
| 恢复终章任务 | `GET /api/v1/stories/{storyId}/final-movies/active` | 返回当前合成进度或最近成功终章 |

Stories 接口沿用阶段一媒体、钱包、报价和任务的基础语义。章节报价与普通报价使用相同积分冻结规则；终章合成任务不冻结积分，但仍要求幂等键。所有公开请求、响应、构造函数、方法、枚举和属性字段必须添加准确中文注释。

## 10. 内容治理与发布约束

- 内容等级继续使用 `GENERAL`、`ROMANCE`、`ADULT_EXPLICIT`；当前海外商店版本最高开放 `ROMANCE`。
- Stories 仅向完成 18+ 确认的用户开放；未完成确认的用户仍可使用符合目录规则的通用能力。
- 不设置常规人工逐条前审；上传素材、提示词和生成结果通过自动规则及模型能力处理。
- 自动策略至少覆盖国家领导人等受限人物、未成年人、明确性内容、非自愿性化内容、违法内容和商店明确禁止内容。
- 应用内提供结果举报入口，后台提供举报查询、策略配置、关系生成开关和全局生成 kill switch。
- 应用内不建设公开作品流、点赞、评论或陌生人社交；外部分享使用系统分享能力。
- `ADULT_EXPLICIT` 默认关闭，正式启用前必须作为独立发布门禁重新确认商店政策、地区规则、年龄体系、支付、监控、回滚和下架风险。
- Google Play 的 AI 生成应用需提供应用内举报并阻止受限内容；非自愿性化 deepfake 属于明确禁止内容。参考 [AI-Generated Content](https://support.google.com/googleplay/android-developer/answer/13985936?hl=en) 与 [Inappropriate Content](https://support.google.com/googleplay/android-developer/answer/9878810?hl=en)。
- Apple 版本需满足用户内容治理、知识产权、隐私和真人内容相关要求。参考 [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。

### 11.1 阶段一后台重构目标与边界

阶段一后台围绕两条客户端链路重建：

1. `首页模板 → 单/双图上传 → 冻结积分 → 固定源视频人物替换 → 异步生成 → 任务结果同步`。
2. `自由创作 → 提示词/参数/图片 → 冻结积分 → 异步生成 → 任务结果同步`。

后台的核心对象统一为“模板及发布版本、模型与工作流版本、用户生成任务与执行记录、积分流水”。当前管理后台尚未上线且没有正式消费方，本轮直接替换阶段一旧信息架构，不保留旧页面、旧字段、别名或双写逻辑；该判断只适用于当前未上线后台。

模板生成阶段只采用固定源视频人物替换策略。封面图、首页 2–3 秒循环视频、详情完整效果片、生产源视频全部独立上传；单人和双人模板分别配置一个或两个人物槽位，并明确“用户照片 1/2 → 源视频人物 A/B”的映射关系。自由创作不使用固定生产源视频，但复用模型、工作流、任务和积分基础设施。

### 11.2 阶段一后台信息架构与页面闭环

侧栏使用六个业务域：`总览 → 客户端运营 → 模板中心 → AI 能力 → 生成任务 → 积分流水`，底部固定“系统设置”。阶段一后台当前页面为：

1. `01 E0-阶段一运营总览`：统一展示上线模板/模型供给、今日任务、生成成功率、积分净消耗、四段运营链路、待办事项、异常任务以及模型、队列、对象存储和积分账本健康状态。该页只做聚合查询和跳转，不直接修改业务数据。
2. `02 E1-客户端首页编排`：管理首页栏目、顺序、上下线时间和栏目版本；只允许投放已发布模板版本。
3. `2A E1-E1A栏目详情与模板管理`：作为首页编排的二级页面，配置单个栏目的模板清单、顺序、排期和启用状态。
4. `03 E1-E2模板库`：按草稿、待测试、可发布、已发布和已下线筛选，展示单/双人类型、规格、价格、绑定模型和版本状态。
5. `04 E2-E6模板详情 · 全量配置`：用 Tab 承载基础信息、客户端展示视频、生产配置、提示词、人物槽位、定价和工作流绑定。客户端展示视频内“首页循环视频”位于“详情效果片（原片）”上方，两者都位于“客户端展示视频”说明下；已发布版本不可原地修改。
6. `05 E6-E7测试生成与发布`：使用测试照片执行完整链路，展示成片、步骤耗时、成本和发布检查；测试成功后仍需运营人工确认。
7. `09 E8-自由创作配置`：管理客户端说明、默认参数、模型列表入口和整体发布状态，不再在本页展示组合积分报价卡。
8. `10 E9-模型服务`：作为自由创作配置的二级页面，从“模型列表”的“编辑”入口进入；表格使用统一后台表格组件，列出模型、能力、状态以及“编辑 / 删除”操作。
9. `11 E9-EA模型编辑 · 组合积分`：配置单个模型的能力范围、输入合同、供应商映射和全部可售参数组合。组合积分按 `比例 × 时长 × 分辨率 × 音频` 完整组合逐行配置，运营直接设置最终积分，不要求按模型基础价与增量公式计算。
10. `14 ED-生成任务`：按用户、来源、模板/模型、任务状态、积分状态和时间筛选，区分业务任务与执行记录。
11. `15 ED-EE任务详情`：展示输入、模板/模型/工作流快照、人物映射、积分流水、执行时间线、错误码和成片，并提供平台补偿重试。
12. `16 EF-积分流水`：展示冻结、成功结算、失败解冻和平台补偿记录，每条流水关联用户、任务、报价快照和幂等标识。

后台页面层级只保留两层：一级业务页和二级详情/编辑页。标题区统一使用“返回按钮 + 页面标题 + 页面路径”组件；路径最多显示 `一级页面 / 二级页面 / 当前 Tab`，其中第三段只是当前 Tab，不代表第三级路由。没有 Tab 的页面只显示两段路径。

阶段一总览的指标口径固定为 UTC 自然日，并在标题区显示统计周期和最近刷新时间：

- “上线供给”分别统计客户端可读取的已发布模板数和已启用模型数，不统计草稿或已下线版本。
- “今日生成任务”按任务创建时间统计；排队数取当前 `QUEUED / SUBMITTED`，失败数取当日进入最终失败的业务任务。
- “生成成功率”以统计窗口内进入终态的任务为分母、成功任务为分子，不把仍在运行的任务计入分母。
- “今日积分净消耗”按成功结算减失败释放与平台补偿计算；冻结积分单独展示，不混入净消耗。
- 待办和发布门禁来自各业务域的可操作状态，点击后进入对应筛选页；服务健康只展示脱敏聚合状态，不展示供应商凭据或内部异常原文。

模板详情采用分栏 Tab，不使用一次性长表单。配置对象统一执行 `草稿 → 测试通过 → 已发布 → 已下线`；已发布版本不可原地修改，编辑时创建新草稿版本。下线只阻止新请求，不删除历史任务与结果。工作流仍然是后端版本化快照的一部分，但当前阶段不提供独立“工作流版本库/工作流版本编辑”页面；运营在模板或模型编辑页绑定已发布工作流，底层版本发布由受控配置流程完成。

### 11.3 人物替换工作流、任务与积分语义

人物替换工作流使用版本化线性步骤：

`校验模板与输入 → 校验照片质量 → 准备源视频与用户照片 → 人脸检测和槽位映射 → 拼接基础/模板提示词 → 提交人物替换模型 → 查询生成状态 → 校验并转码成片 → 保存结果 → 结算积分并完成任务`

- 工作流版本提供通用人物一致性、动作保持与负向约束；模板提供场景专属完整提示词、负向补充和允许变量。创建任务时保存最终提示词快照。
- 创建任务时在同一事务中保存模板版本、工作流版本、模型、人物映射和价格快照，并原子冻结积分。
- 客户端退出或杀掉进程不影响服务端任务；阶段一任务创建后不允许取消。
- 瞬时故障在同一业务任务下自动重试两次，最多形成三条执行记录，不重复冻结积分，也不自动切换备用模型。
- 任一次执行成功即只结算一次；三次执行均失败后进入最终失败并只解冻一次。
- 运营补偿重试不再次扣用户积分，必须记录补偿原因、操作者和新的执行记录。
- 成功任务直接保存成片地址、封面和结果元数据，不新增独立作品实体。App 启动、进入生成记录或 Studio 时同步任务列表，成功任务本身就是结果来源。
- 阶段一成功任务和成片不自动过期；推送通知只作为后续增强，不作为结果可见性的前置条件。

后台发布门禁必须覆盖必填字段、四类资产、人物槽位、工作流发布状态、积分价格和真实测试生成。测试生成成功后仍需运营人工确认成片、成本与耗时，才允许发布到客户端。

### 11.5 阶段三合规后台页面与闭环

阶段三只承接客户端当前已有入口，不新增删除账号等未进入客户端阶段三范围的能力：

1. `01 H0-阶段三合规总览`：展示举报量、处理中工单、历史资产过期、恢复请求、政策版本和导出请求。

4. `05 H4-历史与存储策略`、`06 H4-H5过期与恢复规则`：配置普通任务、生成结果、预览资产的保留期限、到期提示、恢复窗口和清理任务。

举报证据、政策同意记录和数据导出均保存不可变快照与操作日志。后台页面默认不展示永久 OSS 地址、原始凭据或超出工单所需的真人素材。

### 11.6 阶段四 Stories 后台页面与闭环

阶段四建立“故事模板包 → 固定六章 → 章内多个场景模板 → 用户故事实例 → 章节生成版本 → 终章合成”的完整运营链路：

1. `01 J0-Stories运营总览`：展示故事曝光、关系创建、章节付费、六章完结、终章合成、失败退款和待审核配置。
2. `02 J1-故事模板库`、`03 J1-J2故事模板详情 · 基础信息`：配置题材、标签、封面、关系类型、人物槽位、六章结构、内容等级和版本状态。
3. `04 J2-J3六章地图编辑`：固定六章顺序、章节标题、剧情目标、解锁条件和每章场景模板数量。
4. `05 J3-J4章节详情 · 场景模板`：在单章下新增、复制、排序、启停多个具体场景，例如“吵架 · 回家路上 / 校园 / 网吧”。
5. `06 J4-J5场景模板详情 · 资产与提示词`：上传封面、2–3 秒自动循环预览、完整参考效果片和生产源视频，配置人物映射、完整提示词、负向提示词、模型参数、时长、画幅、分辨率和积分价格。
6. `07 J5-J6真实测试与发布`：用测试人物素材执行完整人物替换工作流，核验结果、耗时、成本和内容审核后人工发布。
7. `08 J7-Stories首页与Banner编排`：配置 Video 首页 Stories 模块、关系 Banner 顺序和自动切章策略；预览静音自动播放，不显示播放按钮，卡片内部不允许手滑切章。
8. `09 J8-用户故事`、`10 J8-J9用户故事详情`：按用户、关系、故事模板和状态查询六章进度、已选场景、任务与终章，不直接暴露原始真人素材。
9. `11 JA-章节生成任务`、`12 JA-JB章节任务详情`：查看冻结积分、模板/提示词快照、人物映射、执行记录、多个 Take、选定正片、失败退款和补偿重试。
10. `13 JC-终章合成任务`、`14 JC-JD终章交付详情`：查看六个正片输入、拼接/转码/上传步骤、结果播放、下载分享交付和更换正片后的免费重合成。
11. `15 JE-Stories定价与积分`：配置章节价格、VIP 折扣和积分语义，展示冻结、结算、释放、退款及终章免费合成规则。
12. `16 JF-Stories运营审计`：记录故事、章节、场景、Banner、定价、人工重试和版本发布操作，支持按对象、操作者和时间筛选。

故事模板发布采用版本化流程：`草稿 → 六章配置完整 → 每章至少一个可用场景 → 资产与提示词完整 → 真实测试通过 → 人工发布`。客户端只读取已发布版本；下线和回滚只影响新创建关系，既有关系、章节任务和终章继续绑定创建时的版本快照。

章节预览由运营上传的固定 2–3 秒媒体承载，不触发正式生成和积分扣除。正式任务一经服务端创建即独立于客户端进程运行；App 被杀后，用户再次进入 Stories 时通过关系、章节和活动任务接口恢复进度。单章每次成功生成保留独立 Take，只有用户选定正片后才解锁下一章；更换正片不回退章节，终章按最新六个正片免费重合成。

### 11.8 阶段一后台接口与客户端读取关系

管理接口规划统一使用 `/admin/v1`，客户端接口使用 `/api/v1`。后台写入草稿和发布版本，客户端只读取已发布快照；后台页面不得直接修改客户端缓存或绕过发布门禁写生产读模型。

| 后台页面 | 规划管理接口 | 影响的客户端接口 | 发布与刷新规则 |
| --- | --- | --- | --- |
| `01 E0` 运营总览 | `GET /admin/v1/overview/stage-one?period=today` | 无直接写入影响；聚合目录、任务、钱包和服务健康数据 | 默认实时查询，允许 30–60 秒短缓存；返回各模块 `asOf` 时间和数据完整性状态 |
| `02 E1`、`2A E1-E1A` 首页编排 | `GET/PUT /admin/v1/home-layouts/{layoutId}`、`POST /admin/v1/home-layouts/{layoutId}/publish` | `GET /api/v1/catalog/home` | 发布时生成不可变 `publishedVersion`；客户端按 `ETag` 刷新，旧版本在新版本生效前继续可读 |
| `03 E1-E2`、`04 E2-E6`、`05 E6-E7` 模板链路 | `GET/POST /admin/v1/templates`、`GET/PUT /admin/v1/templates/{templateId}/draft`、`POST /admin/v1/templates/{templateId}/test-runs`、`POST /admin/v1/templates/{templateId}/publish` | `GET /api/v1/catalog/templates`、`GET /api/v1/catalog/templates/{templateId}`、报价和任务接口 | 发布校验字段、四类资产、槽位映射、模型/工作流和真实测试；客户端任务保存发布版本快照 |
| `09 E8` 自由创作配置 | `GET/PUT /admin/v1/ai-create/config`、`POST /admin/v1/ai-create/config/publish` | `GET /api/v1/ai-create/config` | 只管理整体开关、默认项和客户端说明；发布后递增 `configVersion` |
| `10 E9`、`11 E9-EA` 模型与组合积分 | `GET/POST /admin/v1/ai-create/models`、`GET/PUT/DELETE /admin/v1/ai-create/models/{modelId}`、`PUT /admin/v1/ai-create/models/{modelId}/pricing-combinations` | `GET /api/v1/ai-create/config`、`POST /api/v1/generation/quotes` | 删除仅允许未被发布配置和历史快照引用的草稿模型；已使用模型改为停用。组合价格发布后由配置接口一次返回，报价接口最终复核 |
| `14 ED`、`15 ED-EE` 生成任务 | `GET /admin/v1/generation/tasks`、`GET /admin/v1/generation/tasks/{taskId}`、`POST /admin/v1/generation/tasks/{taskId}/compensation-retries` | `POST/GET /api/v1/generation/tasks...` | 补偿重试不再次扣款，必须写操作者、原因和新执行记录；客户端仍使用原业务任务 ID 查看最新状态 |
| `16 EF` 积分流水 | `GET /admin/v1/wallet/ledger`、`GET /admin/v1/wallet/ledger/{entryId}` | `GET /api/v1/wallet`、`GET /api/v1/wallet/ledger` | 账本只追加事实，不允许后台编辑原流水；人工补偿创建新流水并引用原任务和原因 |

管理接口的写操作统一要求后台登录态、角色权限、`X-Request-Id` 和审计原因；发布、删除、补偿重试与人工资产调整还需二次确认。审计日志至少记录对象类型、对象 ID、版本、操作前后摘要、操作者、时间和请求追踪 ID，敏感配置只记录引用名称与存在状态。

## 12. 测试与验收

### 12.1 客户端

- 四个底部入口均可独立访问，Video、AI Create 和 Studio 原有功能行为保持不变。
- Video 首页正确覆盖无故事、单故事、多故事、生成中、已完成和服务异常状态。
- 多个关系的素材、选择、章节、积分记录、生成版本和终章完全隔离。
- POV 与双人模板按合同要求对应素材数量和人物顺序。
- 章节按顺序解锁，重生成保留旧版本，正片切换不回退章节并允许重新合成终章。
- 应用重启后正确恢复章节生成和终章合成任务，不重复创建或扣款。
- 自由创作配置命中有效缓存时先展示缓存并后台刷新；`ETag` 未变化时不重复解析，版本变化时保留仍受支持的用户选择。
- 切换模型、比例、时长、分辨率和音频时只查询本地 `pricingCombinations`；没有完整匹配组合时禁用提交，点击生成后必须以服务端最新报价覆盖预计积分。
- 报价过期、配置版本过期、组合停用、余额不足和幂等冲突均按稳定错误码进入明确页面状态，默认展示英文兜底文案，不透传服务端中文或供应商异常。
- 同一 `Idempotency-Key` 的重复提交只恢复同一业务任务；App 进入后台、被杀或网络切换后依据 `taskId` 和活动任务接口恢复，不根据本地倒计时推断终态。

### 12.2 后端

- 使用 MySQL Testcontainers 验证关系、章节、正片唯一约束和 Flyway 迁移。
- 覆盖并发扣款、重复提交、失败退款、自动拦截退款、章节越级、跨关系版本选择和重复合成。
- 覆盖供应商回调与轮询竞态、终章下载失败、转码失败、上传失败和重新合成。
- 覆盖关系删除后的任务停止、素材清理以及历史作品访问边界。
- 覆盖 `ApiEnvelope`、请求追踪头、UTC 时间、游标分页、稳定错误码、`ETag / If-None-Match` 和短时媒体地址的 OpenAPI 合同。
- 覆盖自由创作配置组合的唯一性与完整性，以及配置发布后旧报价、过期报价、停用模型和被删除草稿模型的处理。

### 12.3 内容与商业化

- 第一章和后续章节均按服务端报价扣积分，不存在客户端隐藏免费逻辑。
- 重生成产生新流水，失败任务不会消耗用户积分，终章合成不扣生成积分。
- 覆盖 18+、受限人物、未成年人、明确性提示词、非自愿性化结果、举报和 kill switch。
- 覆盖导出无强制可见 AI 文案、应用内 AI 说明存在以及来源元数据写入条件。

### 12.4 最终门禁

- 后端全量测试、数据库迁移验证和 OpenAPI 合同测试。
- Android 单元测试、构建和 lint；iOS 无签名构建和对应测试。
- 管理端类型检查与生产构建。
- 英文运行时兜底文案和中文接口注释扫描。
- `.pen` 结构、节点 ID 唯一性和四入口导航一致性校验。

## 13. 已确认决策与实施边界

- 饭圈连续章节是新增重点业务线，通用视频模板和 AI Create 继续保留。
- Video 首页新增 Your Stories 模块，完整档案与章节管理放在独立 Stories 底部入口。
- 底部导航显示文案固定为 `VIDEO → AI CREATE → STORIES → STUDIO`。
- Stories 使用运营配置的固定六章故事模板包；每章可包含多个运营配置的固定场景模板。用户可逐个免费预览 2–3 秒并选中具体场景，正式生成时只替换“我＋TA”人物，不提供单章自由改写。
- Video 首页使用通用 `Story Progress Banner` 承载多个关系故事，支持 `Default / Playing / Completed` 状态；进行中关系每章预览结束后由播放器自动切换下一章，卡片内部不提供横滑、播放按钮或可操作进度条，点击任一 Banner 进入对应关系章节二级页。
- 一个用户可以创建多个关系档案，每个关系使用固定六章首季结构。
- 单人 POV 和双人同框模板均支持，终章从六个用户选定版本合成。
- 第一章不免费；每次生成和重生成均按次扣积分，VIP 通过周期积分与折扣提供价值。
- 首发面向海外英文商店，仅限 18 岁以上用户使用 Stories，应用内无公开社区。
- 当前亲密边界截至亲吻；更高等级内容不混入本版本。
- 导出不强制添加可见 AI 文案，应用内保留 AI 内容说明和可用的来源元数据。
- 本阶段只建设本地与测试能力，不修改生产配置、生产数据库、支付后台、OAuth、证书、DNS 或应用商店控制台。
